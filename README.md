## 给 AI 的阅读规则（先读这 5 行，能省掉大量 token）

1. **本文件就是索引，不要递归遍历或全库 grep。** 全库 81 篇约 9700 行，全量读入既慢又贵。
2. **先定位，再精读**：在下文的「场景导航」里匹配任务 → 拿到确切路径 → 只打开那一篇。
3. **命中不了再查「完整索引」**：按分组表找文件名，别用关键词盲搜。
4. **优先读概述**：`自定义智能体概述.md`、`网页应用概述.md`、`网页应用开发指南概述.md`、`通讯录概述.md`、`组织架构概述.md` 是各自主题的入口，先读它们再决定要不要展开。
5. **不要同时打开两套 API 的同类文档** —— 本库有两对易混 API：Aily 的两套「会话」、通讯录与组织架构的两套「部门/用户」，见下方两处 ⚠️。

## 三、概念速查

| 术语 | 属于 | 含义 |
|---|---|---|
| Session（会话） | 两套 API 都有 | 一次交互上下文；工作流应用里会话是发消息和创建运行的前置 |
| Run（运行） | 工作流应用 | 会话上的一次执行，有状态与结束时间 |
| Message（消息） | 工作流应用 | 从属于某个活跃会话 |
| Skill（技能） | 工作流应用 | 应用可选能力，可查询列表、查详情、直接调用 |
| `agent_artifact_id` | 自定义智能体 | 智能体产出的图片/文件/文档标识，用于下载产物 |
| 附件 ID | 自定义智能体 | 上传文件后返回，发起对话时引用 |
| JSAPI | 网页应用 | 飞书客户端开放接口（H5 可调用） |
| web-meta | 网页应用 | 网页元数据，`page-meta`/`view-meta` 定制容器表现 |
| 免登 | 网页应用 | 在飞书客户端内访问时自动获取当前用户身份 |
| 重定向 URL | 网页应用 | OAuth 2.0 授权后回跳地址，登录类场景必配 |
| User（用户） | 通讯录 | 企业内成员，open_id/user_id/union_id 标识 |
| 用户组 | 通讯录 | 部门之外的用户圈定方式，用于权限管控 |
| 通讯录权限范围 | 通讯录 | 应用可操作的部门/用户数据范围，范围外数据接口报无权限 |
| Employee（员工） | 组织架构 | 管理后台组织架构里的成员，等同于通讯录的 User；`employee_id` = `user_id` |
| `required_fields` | 组织架构 | 查询接口按需指定返回字段，可选值见 `组织架构/字段枚举.md` |
| filter / conditions | 组织架构 | 查询条件表达式（eq/in，多个条件为且），语法见 `组织架构/查询条件用法.md` |

### ⚠️ 两个「会话」不是一回事

`飞书aily/自定义智能体/` 与 `飞书aily/工作流应用/` **是两套不同的 API**，各自的「创建/删除会话」接口互不通用。

- 要跟**已发布的智能体**对话 → 用 `自定义智能体/` 下的接口
- 要驱动 **Aily 工作流应用**（会话 + 消息 + 运行 + 技能）→ 用 `工作流应用/` 下的接口

定位错了会白读一整组文档，先按上面这句判断。

### ⚠️ 两个「部门/用户」也不是一回事

`通讯录/`（contact-v3）与 `组织架构/`（directory-v1，管理后台-组织架构）**是两套不同的 API**。两边都有「搜索部门」「批量获取部门信息」等同名文档，但路径、鉴权、入参和返回结构完全不同，互不通用。

- 要**读取/管理企业通讯录**（用户、部门、用户组、权限范围，面向应用）→ 用 `通讯录/` 下的接口
- 要**管理组织架构**（员工入转调离、HR 同步、按条件筛选、字段级权限，面向企业管理员）→ 用 `组织架构/` 下的接口

一句话判断：应用里查人查部门 → 通讯录；管理员管员工生命周期/HR 系统同步 → 组织架构（其 Employee 等同于通讯录的 User）。
